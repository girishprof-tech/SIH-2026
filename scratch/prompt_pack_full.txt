## PHASE 2 — Fix the frontend/simulation sync bugs

```
In frontend/src/App.tsx, robot/conflict/obstacle state comes from the WebSocket
(useFleetSocket.ts, updated every tick) while task/status/metrics/chaos state comes from
separate REST polling on a 1500ms setInterval (api.tasks(), api.status(), api.metrics(),
api.chaosStatus()). These two update cadences are not synchronized to the same simulation
tick, which causes visible UI inconsistency (e.g. task list and robot positions reflecting
different ticks).

Fix this by:
1. Including task state, or at minimum a task-state version/hash, in the WebSocket
   TICK_UPDATE payload broadcast from backend/backend/app/main.py's `_telemetry_forwarder`,
   so the frontend can derive task state from the same tick as robot state instead of a
   separate poll.
2. Reducing REST polling to only what genuinely can't ride the WebSocket (e.g. chaos toggle
   status set by a human action elsewhere), and documenting why each remaining poll exists.
3. Adding a visible "last synced tick" indicator per data source in the UI (or a single
   unified one) so any future desync is visible to the user instead of silently causing weird
   rendering.
4. Auditing backend/backend/app/main.py's `_is_udp_port_bound(9001)` fleet-detection check —
   this is a fragile way to decide whether to spawn robot processes. Add a startup log line
   and a `/api/health` field that explicitly reports "spawned new fleet" vs "attached to
   existing fleet" vs "no fleet detected, robots not running", and surface that state in the
   frontend's ControlBar so a broken detection doesn't look like "the simulation isn't working"
   with no explanation.
5. Add an explicit error boundary / connection-lost banner in App.tsx for when the WebSocket
   disconnects and reconnection is failing repeatedly (useFleetSocket already tracks
   'reconnecting'/'disconnected' status — surface it more prominently than the current small
   footer text).

Run the existing test suite (test_decentralization.py, verify_no_swap.py, test_fuzz_*.py)
after these changes and show me the output.
```
